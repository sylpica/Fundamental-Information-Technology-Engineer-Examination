## 確認した事項

- 入力式（drill.yaml の type: input）：accept はすべて正答の値か、その全角・「回」付きの表記だけで、誤答を受け付けるものはない。採点は `src/lib/text.ts` の isAcceptedInput で、正答の選択肢の文言も受け付ける（NFKC・空白・大小・マイナス記号を正規化）。選択式に切り替えたときの c と a の対応も全問確認した。
- 短絡評価：and の右辺で範囲外参照が起こり得る B-DRL-019・076 は、問題文に「左側の条件が偽のとき右側の条件を評価しない」の前提がある。
- verify：`npm run content` で全問の verify（result・cases）と sim が通ることを確認。cases を持つ B-ALG-416・421、B-DRL-088・089・090 は、fills（または c）と c の位置の対応を確認し、正解以外の選択肢がいずれかのケースで落ちることを手で確かめた。
- B-SEC-105（DMARC は SPF か DKIM の一方の成功とアライメントで合格）、B-SEC-108（36⁸ ÷ 10¹⁰ ≒ 282 秒 ≒ 4.7 分。誤答の 10⁹・10⁸・10⁷・半分の値も再計算）を確認。
- 重複：sec 系の各題材を content/questions 全体で grep。A 側の定義問題（ハイブリッド暗号、DMARC）とは形式・問い方が異なり、実質重複はなかった。
