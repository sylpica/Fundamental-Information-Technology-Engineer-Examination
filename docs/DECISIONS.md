# 設計判断の記録

| 日付 | 判断 | 理由 |
| --- | --- | --- |
| 2026-10-20 | シラバスは Ver.9.2 に準拠し、2027年度の新制度案は採用しない | 新制度は案の段階で、範囲は現行と同じと説明されている。確定後に JSON を差し替える |
| 2026-10-20 | 問題はオリジナル中心。IPA 公開問題（令和5〜8年度 CBT）は出典・改変を明記して追加予定。図表を再現できない問題は rejected | IPA FAQ の利用条件に従う。旧午前試験の過去問は利用しない |
| 2026-10-20 | 教材は YAML で作成しビルド時に厳格検証、エラーが一つでもあれば失敗 | 正答・解説の誤りを公開前に機械的に止めるため |
| 2026-10-20 | 正解の選択肢の解説だけを「正解です」で始める規約 | 正答と解説の食い違いを自動検出するため |
| 2026-10-20 | 選択肢は表示時にシャッフルし、解説で選択肢記号を参照しない | 位置の暗記を防ぐ。記号参照はビルドで検出 |
| 2026-10-20 | 計算問題は独立した検算式、擬似言語は全選択肢を実行、SQL は SQLite で実行して正答を検証 | 作成者の思い込みによる誤答を防ぐ |
| 2026-10-20 | 科目A 模試の分野配分はシラバスの末端論点数に比例（独自方針） | 公式の分野別出題数は公表されていない |
| 2026-10-20 | 合格可能性・IRT 得点は表示しない | 公式の項目パラメータがなく、推定は誤解を招く |
| 2026-10-20 | ハッシュルーティング・相対 base | GitHub Pages のサブパスで 404 にならないようにする |
| 2026-10-20 | 教材 JSON は Service Worker のプリキャッシュから外し、アプリ側で Cache Storage に保存 | 教材だけの更新で全体を再取得しないため。オフライン準備状況を正確に表示するため |
| 2026-10-21 | 教材作成を分野ごとに並行作業し、統合時に用語の重複を `tools/fix-glossary-dups.py` で解消（後から読まれた重複項目を削除） | 作業効率。重複はビルドで必ず検出される |
| 2026-10-21 | 擬似言語の `÷` は実数除算とし、整数型変数への代入時に切り捨てる。問題文で必ず前提を明示する | IPA 別紙2は「÷」の整数除算規則を明記していないため、問題ごとに前提を書く方式にした |
| 2026-10-21 | シミュレーターにクラス定義などの実行オプションを渡す | 連結リスト問題のシミュレーターが実行時エラーになる不具合の修正 |
| 2026-10-21 | 公開条件を `tools/check-release.ts` で機械判定（verified 1,000問以上、網羅率80%以上、23中分類、科目B各区分の最低数、参考書・講座・ドキュメント） | 完成判定を主観に頼らないため |
| 2026-10-21 | 擬似言語の `a ÷ b の商` / `a ÷ b の余り` は 0 以上の整数を正の整数で割る場合だけ定義し、それ以外は実行時エラーにする（通常の `÷` は実数除算のまま） | IPA 別紙2は商・余りの符号の扱いを定めておらず、公開問題の使用例はすべて非負整数。未定義の挙動を黙って決めない |
| 2026-10-21 | 「繰返し処理を終了する」は最も内側の繰返しを抜け、「αの行から始まる繰返し処理を終了する」は見出し行末の注釈 `// α` を持つ繰返しまで抜ける。名前付きの終了は関数をまたがない | 公開問題の記述に合わせた最小の解釈。注釈の付いたループ見出しだけを名前の対象にする |
| 2026-10-21 | `iの正の平方根` は実数、`…の整数部分` は切捨て、`…の2乗` は自乗、`…の文字数` / `sのi文字目の文字` は 1 始まり、`{n行m列の v}` は行ごとに別の配列、`…の要素の和` は二次元配列も全要素の和、`－∞` は負の無限大 | 公開問題の文面から一意に読み取れる意味だけを実装。範囲外の文字位置・行番号はエラー |
| 2026-10-21 | `…の全要素の値を要素番号の順に空白区切りで出力する` は 1 行（空白区切り）、`xの値とyの値をこの順にコンマ区切りで出力する` は 1 行（コンマ区切り・空白なし）として出力する | 問題文は区切り文字しか示さないため、行は 1 回の出力文につき 1 行とした |
| 2026-10-21 | 日本語の比較表現（`…が…と等しい` など）を正規表現による置換からトークン解析に変更。`(i mod 4)が0と等しい` のように左辺に括弧や演算を含められる。優先度は関係演算子と同じ | 括弧付きの左辺を扱えない不具合の解消。左辺・右辺は加減算の式まで |
| 2026-10-21 | `…のいずれかの要素の値が…と等しい` / `…の要素のいずれかに…の値が格納されている` / `…のいずれにも…格納されていない`、`xにordersの要素を順に代入する`（for-each）、`…の値を n 増やす`、`aとbの値を入れ替える`、`…に含まれる文字列を重複なく辞書順に格納した配列`、`…の複製から値が…である要素を除いた配列` を構文として追加 | 令和5〜8年度の公開問題で、プログラム中の文として現れる記述。文字列の辞書順は文字コード順 |
| 2026-10-21 | 括弧が閉じていない行、二項演算子・コンマ・「を」・「である」で終わる行は次の行と連結して 1 文として解釈する（行番号は先頭行） | 公開問題の複数行にまたがる宣言・式を原文の改行のまま掲載するため |
| 2026-10-21 | 検証ツールの `verify.result.of` に `output:N`（N 番目の出力行）と `condtrue:β`（注釈 `/*** β ***/` の行の条件式が真になった回数）を追加 | 「最初に実行したときの出力」「条件式が真となる回数」を問う公開問題を機械検証するため |
| 2026-10-22 | 難易度を 4 段階（1 基礎 / 2 標準 / 3 応用 / 4 高難度）に拡張し、追加バッチ H2 の問題には出題範囲の根拠（scope）・前提知識・難度要因を必須化。本番形式の模擬試験と「今すぐ学習」には高難度（4）を含めず、「高難度特訓」と難易度フィルターで出題 | 95点以上を目指す学習のための難問を増やしつつ、模擬試験が実際より不自然に難しくならないようにするため |
| 2026-10-22 | 応用・高難度問題で間違えたときに、同じ論点の基礎・標準問題へ戻る復習ボタンを演習結果に追加 | 難問で崩れた理由が基礎の理解不足である場合に、すぐ戻れるようにする |
| 2026-10-22 | `tools/check-release.ts` の H2 条件（2,000 問以上、追加 608 問以上、追加の 70% 以上が応用・高難度、scope 必須）は、作業中は表示のみとし、完成判定時に `ENFORCE_H2=1` で強制する | 作業の途中で CI が止まらないようにしつつ、完成条件は機械判定するため |
| 2026-10-29 | Pull Request の保留を解除する。品質ゲート（テスト・ビルド green、独立レビュー合格）通過後は、PR の作成とマージまで自律的に行う | ユーザーが「PRを勝手にやってもいいです」と明言し、FE にも適用される明示許可として伝達されたため。従来の「ユーザーが明示するまで PR を作らない」はこの明示をもって解除 |

| 2026-11-04 | 科目Aの問題の分野（category）は、ファイルの category ではなく主論点（topic の先頭）の中分類番号から教材ビルドで決める | H2 ファイルの `'01'` 表記で 236 問が別分野になり、模試の分野配分・参考書・分野別分析から漏れていた。ファイルと主論点の中分類が食い違う問題も 12 問あった |
| 2026-11-04 | 用語の分野はシラバスの中分類名に統一する。中分類に対応しない作業上の名前（補遺など）のファイルでは、用語を使う問題の分野→シラバスの用語例→既定値の順で決め、用語ごとに `category` を指定することもできる | 辞典の分野フィルターに `06` などの番号や同義の分野名が並んでいた |
| 2026-11-04 | `depth` は quick / deep のみ（ビルドで検証）。科目B模試のセキュリティも本番形式（deep）の事例問題だけから出題する | `depth: standard` の 40 問がどの出題対象にも入らず、IPA の長文事例 4 問が短時間学習に入っていた。短い一問一答が本番形式の模試に混ざらないようにする |
| 2026-11-04 | 全アプリ共通 UI ルール（スクロール削減・文字切れ禁止・説明文は下部・上部バーはコンパクト）を適用。一覧の問題文は文字数で切らず最初の一文を表示し、長い一覧（辞典・読解）は「さらに表示」で段階的に描画する | ユーザー指示（2026-11-03）。辞典は 2,712 語を一括描画してスマホで約 460 画面分になっていた |
| 2026-11-10 | 全件監査で過大だった難易度ラベルは実態に合わせて下げる（戻さない）。その結果 H2 の「応用・高難度 70% 以上」が未達（59.8%）になったため、監査完了後に不足分を本物の応用・高難度問題の追加（作成者と別担当の独立レビュー付き）で補う | 監査前の 87.7% はラベルの過大評価による見かけの値で、ラベルを上げ直して条件を満たすことは品質基準を下げることになるため |
| 2026-11-11 | **H2 の「応用・高難度 70% 以上」は現状の 54.1%（応用 297・高難度 33／610 問）でユーザー確定。70% に寄せるための問題の追加・改修は行わない**（ユーザー指示 2026-11-11）。したがって `ENFORCE_H2=1 npm run check:release` は、この 1 項目が既知の未達として残る。過大だった難易度ラベルは戻さない（2026-11-10 の判断を維持） | 全件監査で、複数段階・複合の基準を満たさない問題のラベルを実態に合わせて下げた結果。比率のためにラベルを上げ直す・新規に書き足すことはしない |
